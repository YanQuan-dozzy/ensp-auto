# PRD：ensp-auto

> 产品需求文档。文档中的决策已于设计评审阶段逐项收敛，不留「看情况」项。

## 1. 背景

### 1.1 现状

参考原型 `ensptomcpfortrae-main` 提供了 eNSP 设备管理能力，但存在结构性缺陷：

| 缺陷 | 影响 |
|---|---|
| `mcp_server.py` 只是无状态 HTTP 转发壳，业务逻辑全在 `app.py` | 「MCP 接口」无独立价值，无法形成可扩展的能力层 |
| 状态是三个模块级全局字典（`devices` / `device_names` / `topology_data`） | 设备命名、拓扑数据重启即丢，无持久化 |
| 通信层固定 `sleep(1.5)` + 单次 `recv(8192)` | 慢、不可靠，长回显必然截断 |
| 无 `---- More ----` 分页处理 | 长输出直接卡死或丢失 |
| `decode('gbk', errors='ignore')` | 静默丢弃无法解码的字符，输出不可信 |
| 无并发保护 | 多客户端同时操作同一设备会串包 |
| **设备报错被当成功返回** | 最致命：AI 会带着错误结果继续推理 |
| Web UI 为单文件原生 JS | 无法组件化，视觉与交互上限低 |

### 1.2 机会

eNSP 是网络工程教学与实验的主流模拟器，但操作方式仍停留在「逐个设备点开、逐条敲命令」。
网络实验的价值在于**验证设计是否正确**，而不是把时间花在重复敲配置上。
现有 AI 工具（Trae / Claude 等）虽能通过 MCP 调用设备，但缺少领域上下文（拓扑、视图、快照），
只能当「远程遥控器」，无法承担端到端实验。

## 2. 产品定位

**一句话**：eNSP 网络实验的 AI 代理工作台 —— 说目标，不看过程；要看过程时，每一步都在。

**与「AI + 终端」工具的本质区别**：
本产品不是给终端套一个聊天框。代理能自主闭环，是因为它拥有领域能力 ——
能读拓扑、能识别设备视图、能在改配置前自动快照、能在失败时回滚、能把回显结构化判定成败。
这些能力本身就是产品的主体，UI 只是它的观测窗。

## 3. 目标用户与场景

### 3.1 用户

| 用户 | 诉求 |
|---|---|
| 网络工程学习者 | 快速搭起实验环境，把精力放在协议理解而非敲命令 |
| 网络课程教师 | 一键生成实验环境、批量配置、导出实验报告 |
| 网络运维/工程师 | 快速验证配置思路、巡检设备状态、记录变更 |

### 3.2 核心场景

**S1 一句话搭实验（主场景）**
> 用户：「在三台设备上跑通 OSPF，互联网段 10.0.0.0/24」
> 代理：扫描 → 识别设备型号与接口 → 配置前快照 → 下发 IP 与 OSPF 配置 → 读回显校验邻居状态 → 不达期望则修正 → 输出实验报告

**S2 配错诊断**
> 用户：「R1 和 R2 的 OSPF 邻居起不来，看看为什么」
> 代理：读取双方配置与接口状态 → 比对定位（网段不匹配 / 区域不一致 / 接口未 up）→ 给出结论与建议，**默认不改配置**

**S3 状态巡检与留档**
> 用户：「把当前所有设备的配置导出一份」
> 代理：遍历已连接设备 → 采集 `display current-configuration` → 落库为快照 → 导出汇总

**S4 手动精调**
> 用户直接在 xterm 终端里敲命令，AI 面板可随时插话解释回显或生成下一段配置

## 4. 设计原则

1. **能力在代理，页面在界面。** 渲染层不持有任何特权；所有设备操作经主进程。
2. **自主但可控。** 放开的只读能力，收紧的写能力；破坏性操作一律闸门。
3. **回显必须可信。** 通信层的输出要么是干净的，要么显式标注失败 —— 绝不给代理噪声。
4. **不引重依赖。** 能用标准库/单一 SDK 解决的不引框架；工具循环领域强耦合，自研优于套壳。
5. **可观测。** 代理的每一步（计划、工具调用、原始回显、判定理由）都必须在 UI 可见可回放。
6. **中文优先。** 界面、提示、报告默认中文；编码全程 UTF-8。

## 6. v0.1 范围

**交付目标**：纵向打通最小闭环，证明「一句话到结果」在 eNSP 上跑得通。

### 包含

- 扫描（自定义端口范围）→ 连接 → 断开，设备别名持久化
- xterm 终端可交互，ANSI/分页/编码全部正确
- 通信层提示符状态机 + 错误结构化识别
- AI 面板：配置模型端点 → 自然语言下达任务 → 代理自主执行**只读**操作
  （扫描设备、跑 `display`/`show` 类命令、读回显作答、结合多设备状态给出结论）
- 执行轨迹可见、可中断
- 三栏 UI + 深浅双主题的设计令牌层从第一天立起

### 不包含（推到后续迭代）

- 拓扑画布与拓扑解析（F-5.x）
- 配置变更下发、快照事务与回滚（F-4.1–F-4.5 中除闸门框架外的部分）
- MCP 对外接口（F-8.x）
- 会话树回溯、消息排队（F-3.4、F-3.5）
- 打包分发（开发期直跑）

> **注意**：v0.1 虽不含配置下发，但**必须**把闸门与快照的接口预留出来
> （`AgentRuntime` 与 Tool Registry 的风险等级字段），否则 v0.2 要返工。

## 7. 验收标准

v0.1 通过的标准（逐条可检验）：

1. 应用启动后能在 10s 内完成一次 2000–2050 全区间扫描并列出结果。
2. 连接某设备后，在终端执行 `display version`，输出完整、无乱码、无截断，末尾提示符正确。
3. 在终端执行一条长输出命令（如 `display current-configuration`），分页自动推进至结束，无需人工按键。
4. 对同一设备，终端输入与代理命令交替执行 20 次，无一例串包或回显错位。
5. 故意输入错误命令（如 `displa`），返回结果被标记为失败并带原始错误文本，不被当作成功。
6. 在 AI 面板输入「列出所有设备的型号和接口状态」，代理自主完成扫描、连接、读取，并给出结构化结论。
7. 任务执行中点击中断，代理在 2s 内停止，已产生的中间结果保留在轨迹中。
8. 切换浅色主题，界面与终端配色同步生效，无残留深色块。
9. 关闭应用重开，设备别名仍保留。
10. 冷启动到可交互 < 3s（不含网络）。

## 8. 非功能需求

| 项目 | 要求 |
|---|---|
| 编码 | 源文件全 UTF-8；设备回显 UTF-8 优先、GBK 回退，禁止静默丢字 |
| 性能 | 扫描 51 个端口 ≤ 10s；单条命令回显上限 512KB，超出截断并标注 |
| 体积 | 单 exe 便携版目标 < 150MB（不含模型权重） |
| 离线 | 除模型 API 外无外部网络依赖；xterm/字体等资源本地打包，不走 CDN |
| 安全 | 仅访问 `127.0.0.1`；密钥存系统凭据库；破坏性操作强制闸门 |
| 可观测 | 代理每次工具调用的参数、原始回显、耗时、判定均可查看与导出 |
| 兼容 | Windows 11 为主；架构上不绑定平台，macOS/Linux 可后续适配 |

## 9. 明确不做

对应 README 的安全红线段落，此处展开为产品级约束：

- **不做网络扫描器。** 只探测 `127.0.0.1`，端口范围可配但不允许填非本机地址。
- **不做认证绕过。** 不提供密码猜测、爆破、默认口令穷举；设备启用认证时如实提示。
- **不做无人值守的批量配置。** 批量操作必须经一次显式确认，且提前完成全部快照。
- **不做多实例共享设备。** 同一端口设备在同一时刻只有一个会话持有者，避免配置互相覆盖。
- **不做无法回滚的修改。** 未成功取得配置快照前，拒绝执行任何配置变更。
- **不保存明文密码。** 凭据交给操作系统凭据库，应用自身不留存。

每个版本独立可验收，前一版本不完成不进入下一版本。
